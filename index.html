Your GPU job is billing.
Is it actually training correctly?

ComputeFence is a free CLI that runs in about 30 seconds before a fine-tuning job starts and catches silent configuration failures, such as CUDA quietly falling back to CPU or checkpoints written to a disk that disappears when the pod stops.

$ pip install computefence && computefence doctor
# or, with no install:
$ uvx computefence doctor

What it catches

  • CUDA silently falling back to CPU, or the GPU not being visible to PyTorch
  • HuggingFace cache (HF_HOME) writing to ephemeral disk instead of a persistent volume
  • Accelerate config set up for more processes than there are GPUs (when a config is present)
  • GPU architecture mismatches: flags a GPU whose compute capability isn't supported by the installed PyTorch build
  • Low free disk space on the paths your job writes to

Built for QLoRA, LoRA, Unsloth and Axolotl fine-tuning on rented GPU pods: RunPod, Vast.ai, Lambda Labs.

What it doesn't catch

Training script correctness, learning rate issues, mid-run pod failures, export-stage out-of-memory errors, and merge integrity. It is a pre-flight check, not a monitor.
